# AI Component Loop — фронтенд-демо паттернов AI-Scientist-v2

Минимальный самодостаточный прототип, переносящий ядровую идею **AI-Scientist-v2** в браузер:
итеративный агентный цикл **draft → исполнение в песочнице → vision-ревью → improve**,
с выбором лучшего результата.

Без сборки: UI — `index.html`, мост к Claude CLI — `bridge.mjs`, чистая логика
(вынесена для тестируемости) — `core.js`.

## Запуск

### Вариант A — без API-ключа, через авторизованный Claude CLI (рекомендуется)

Если у вас установлен и залогинен [Claude Code](https://code.claude.com) (`claude`),
ключ не нужен вообще: локальный мост запускает CLI как подпроцесс, а он использует
свою авторизацию.

```bash
# из этой папки
node bridge.mjs
```

Откройте `http://localhost:5173`, выберите провайдер **«Claude CLI (локальный мост)»**.
Мост сам отдаёт страницу (тот же origin → без CORS) и проксирует запросы в `claude -p`.
Зависимостей нет — только Node и установленный `claude`.

### Вариант B — без ключа, Mock-режим

```bash
npx serve .          # или: python -m http.server 8000
```
Провайдер **Mock** детерминированно показывает всю петлю без сети и без ключей.

### Вариант C — свой API-ключ (Anthropic / OpenAI)

Запустите как в варианте B, выберите Anthropic/OpenAI и вставьте ключ.
Ключ остаётся в браузере и уходит только в API провайдера.

### Режимы
- **Mock** — без ключей и без сети: draft со специально внесённой ошибкой →
  debug чинит → improve стилизует → «готово».
- **Claude CLI** — реальная генерация и vision-ревью через локально авторизованный
  `claude`, без API-ключа. Нужен запущенный `node bridge.mjs`.
- **Anthropic / OpenAI** — свой API-ключ. На каждой итерации генерируется реальный
  компонент, снимается скриншот (`html2canvas`) и vision-модель его оценивает.

## Интерфейс

- **Задача** — что построить (описание).
- **Фреймворк** — React (JSX) / Vue 3 / HTML+CSS (vanilla). Меняет и промпт
  генерации, и шаблон песочницы (какой рантайм грузить).
- **Код дизайна** — редактируемое поле с подсветкой синтаксиса (highlight.js) и кнопкой **✨ Сгенерировать** внутри:
  нажал → код сгенерировался прямо в поле и сразу отрисовался в превью. Код можно
  править вручную; кнопка **▶ Запустить петлю** стартует с того, что лежит в этом поле
  (или генерирует с нуля, если пусто), и по ходу итераций обновляет его.
- **Превью** — sandboxed iframe с живым результатом; рядом — vision-ревью и дерево попыток.

## Как устроен мост (`bridge.mjs`)

Браузер не может шеллить CLI напрямую, поэтому крошечный Node-сервер (без зависимостей):

| Эндпоинт | Что делает |
|---|---|
| `GET /*` | отдаёт статику демо (тот же origin, без CORS) |
| `POST /api/llm` | `claude -p "<system>\n\n<user>" --output-format json` → `{text}` |
| `POST /api/vision` | пишет PNG во временный файл → `claude -p "Read the image at <path> ..." --allowedTools Read` → `{text}` |

Важные детали реализации:
- claude запускается из **нейтральной tmp-директории** (`cwd: os.tmpdir()`), иначе он
  подхватил бы CLAUDE.md/git-контекст текущего проекта и повёл себя как агент, а не
  как чистая генерация.
- text-режим идёт **без инструментов**, vision — только с `Read` (может лишь прочитать
  временный скриншот; ни записи, ни шелла).
- сервер слушает только `127.0.0.1`.

## Ключевые идеи, перенесённые из проекта

1. **Изоляция исполнения.** Сгенерированный код запускается только в sandboxed `iframe`
   с жёстким таймаутом — никогда `eval()` в основном потоке. Это прямой аналог
   запуска кода в отдельном процессе в `interpreter.py`.
2. **Не один ответ, а дерево попыток.** Если рендер падает — узел `debug`; если работает —
   узел `improve`. Прогресс и провалы сохраняются в `journal`.
3. **Vision как сигнал качества.** Модель «смотрит» на скриншот и возвращает score+замечания,
   которые идут в следующий шаг `improve`.
4. **Structured output.** Ревью возвращается строгим JSON `{score, summary, issues}` —
   как function-calling схемы в проекте.

## Замечания по безопасности

- `iframe` использует `sandbox="allow-scripts allow-same-origin"`. `allow-same-origin`
  нужен только чтобы `html2canvas` снял скриншот содержимого. В продакшене лучше
  снимать скриншот на сервере (Playwright), а песочницу держать строже
  (`allow-scripts` без `allow-same-origin`).
- Это учебное демо. Не исполняйте произвольный недоверенный код без изоляции.

## Тесты

Чистая логика (без DOM) вынесена в `core.js` и покрыта юнит-тестами на встроенном
раннере Node (`node:test`, без зависимостей и без сборки):

```bash
npm test          # = node --test
```

`core.js` подключается обычным `<script>` (работает и с `file://`), а в тестах
импортируется как CommonJS-модуль — один источник правды для браузера и тестов.
Покрыто: `extractCode`, `parseReviewJson`, `escapeHtml`, `bestNode`,
`buildSrcdoc` (react/vue/vanilla) и mock-петля (`mockGenerate`/`mockReview`).
